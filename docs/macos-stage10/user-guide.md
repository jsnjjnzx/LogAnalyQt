# 第 10 阶段 Mac 使用说明

本说明适用于 macOS 的 SSH 实时监控、安全凭据和协议 SMB 同步。新版工作台与原界面使用相同后端；本阶段保留 Windows 原行为，没有新增 Windows 实现或完成 Windows 实机验收。验证结果及边界见 [验收记录](acceptance.md)。

## 便携目录与系统凭据

继续把 `LogAnalyQt.app` 与 `LogAnalyQt.ini`、`protocol_xml/`、`preset/`、`log/` 放在同级目录；SSH 主机信任记录也保存在该目录的 `ssh-known-hosts.json`。本阶段没有迁移到用户数据目录。应用所在目录须允许当前用户写入；出现配置保存、信任记录或协议写入失败时，先检查报错路径及目录权限。

SSH 密码和既有 AI 密钥使用 macOS 系统钥匙串，分别保存在独立服务域中。复制便携目录到另一台 Mac 不会同时复制系统钥匙串密码，需在目标机器重新配置。程序不会把已保存密码回填到输入框；“已保存”只表示当前目标的凭据状态。

系统凭据访问及共享目录操作在后台执行。遇到 macOS 授权提示，请在系统提示中处理；等待期间主界面仍可使用。操作已受理、正在等待或系统已接手，都不代表保存、连接或同步已成功，应以对应完成结果为准。

## SSH 实时监控

1. 打开“实时监控”，填写主机、端口、用户名。这三个字段共同决定所用密码；更换其中任何一项都会重新核验目标，不借用旧目标密码。
2. 输入本次连接密码后点击“连接”。这次输入不会自动持久保存；需要下次复用时，单独点击“保存密码”，等待完成提示。
3. 若当前目标显示已保存密码，可以让密码输入框保持空白，再点击“连接”。“清除已存密码”只清除当前绑定目标的系统凭据，不会清除主机信任记录。
4. 首次遇到该主机和端口时，程序展示主机、端口、算法及 `SHA256:` 指纹。通过独立可信渠道向管理员核对后，才点击“已核对，信任并继续”。拒绝、关闭或取消都不会授权认证；在信任记录成功保存之前，程序不发送密码认证。
5. 连接成功后使用终端命令输入、日志搜索及复制等原有功能。连接失败时查看状态栏错误；等待或重连时可以取消，迟到的凭据读取或首次信任确认不会重新启动已取消连接。

保存或清除凭据时，“处理中”表示系统操作尚未完成。出现错误时保留输入及旧配置，按错误处理后重试；不要把等待超时理解为钥匙串事务已撤销。已经完成的存储事务也不会因关闭页面而自动回滚。

### 主机密钥变化

已保存主机密钥发生变化时，程序拒绝连接并停止自动重连，不提供直接覆盖按钮。先停止连接，通过独立渠道核对是否确为服务器正常换钥。

确认需要更新记录后，完全退出应用，备份同级 `ssh-known-hosts.json`，只删除已核实端点对应的 `[host]:port` 单条记录，保留其他记录及有效 JSON 格式；重新打开应用并连接，再核对新指纹。信任文件损坏或无法读取时同样需要人工检查，不要通过清空全部信任记录绕过错误。详细工程说明见 [SSH 安全测试](../../tests/SSH_SECURITY_TESTS.md)。

## SMB 协议同步

1. 打开“协议同步”，在“网盘路径”输入共享及协议子目录，例如 `smb://server/share/protocol_xml`。不要在地址中加入用户名、密码、查询参数或片段。
2. 点击“连接”，在 macOS/Finder 的系统窗口完成认证。Mac 版同步页面不收集 SMB 用户名或密码，也不会把密码拼入地址或命令。
3. 等待程序确认系统实际挂载来源与输入主机、共享匹配，并确认子目录可访问。Finder 已打开不代表连接成功；同一来源存在多个不同挂载而无法唯一确定时，程序会报错，不会猜选一个目录。
4. 连接和状态读取完成后，查看文件名、本地及网盘版本、日期和同步方向。`↑` 表示待上传，`↓` 表示待下载，`✓` 表示一致；远端缺失会明确显示待上传。先核对目标及方向，再使用单项“同步”或“一键同步”。
5. 点击“差异”后等待读取完成。读取失败会报告错误，不会把不可读文件当成空文件或把旧差异当成新结果。同步完成后查看结果中的上传、下载、跳过及失败明细。

“取消等待”只停止应用等待连接，不会强杀 Finder 或卸载用户的共享卷。取消同步或关闭页面会使当前等待失效，但不能保证撤销已提交的文件写入；已经提交的下载仍会通知程序重载。取消后再次操作前，等待正在退出的后台操作结束。

同步写入使用临时文件和原子提交保护既有目标；下载还会校验 XML 及对应协议规则。权限、网络或文件校验失败会明确报告。公司共享的写入目前尚未完成真实环境验收，详见 [验收记录](acceptance.md)。

## 旧明文配置迁移

应用只在有充分身份依据时迁移旧密码。迁移过程先保存到系统安全存储并读回比较，再重新检查 INI 原字段没有变化，最后删除旧字段并检查配置写入结果。系统存储失败、目标冲突、源字段变化或 INI 清理失败都会保留可恢复信息并报告，不制作额外明文备份。

- **旧 SSH 密码**：只有旧 INI 明确保存了主机、端口和用户名时，才绑定到该目标。身份缺失时不猜默认主机；目标已有不同安全密码时不自动覆盖，两份原值保留待人工处理。
- **旧 SMB 账号密码**：旧 `protocolSync` 未保存可证明归属的共享地址，因此只保全到源 INI 身份派生的 `legacy-unbound` 隔离项。该项与新输入的共享无关，不会自动用于连接，也不会向 Finder 代填。后续 SMB 认证仍由用户在系统窗口完成。

迁移报错时先保留原 INI 和当前便携目录，处理提示后重试。无需把密码粘贴到日志、问题报告或聊天中；提供脱敏错误与操作步骤即可。
