## 结果

受控完整应用的三轮 CPU 中位数从 **8.29% 降至 6.22%**，降低 **24.99%**。100% 表示占满一个核心。**30% 的 CPU 目标未达到**。11 类交互操作的 P95 均不超过 25 ms，现有功能回归通过，2 MiB/s 持续十分钟通过。

用户在 5 MiB/s 测试期间明确表示现有测试已满足其要求，无法继续保持前台。本轮立即停止剩余测试：保留约五分钟阶段统计，不再进行 5 MiB/s 的完整十分钟验收及完整应用的六十分钟内存验证。第一阶段单页面的六十分钟结果不能替代本轮完整应用的长测。

## 实际改动

1. 日志普通文字限制为可见宽度内的一行，减少屏幕外字符的绘制几何。完整模型文本保留，搜索、复制、长行报文提取和解析继续使用完整内容，选中时仍按需创建原有 TextEdit。实现采用 Qt 自带的单行显示限制，见 [Qt Text 文档](https://doc.qt.io/qt-6/qml-qtquick-text.html#maximumLineCount-prop)。
2. 前台批量提交由 150 ms 调整为 180 ms；后台仍为 500 ms，积压批次仍按原有预算续处理。以实测 P95 接收延迟和独立操作响应作为约束。
3. 在已有测试构建中加入完整应用测量入口、前台状态检查和逐项交互到画面的测量。正常启动不启用测试入口。

生产优化仅涉及 `LiveLogDialog.qml` 和 `SshTerminal.cpp`。没有更换渲染内核、缩小历史容量、关闭功能或减少接收数据。没有添加依赖。原有 Main.qml、LogBackend、Windows 配置脚本等 37 个初始记录文件逐一校验保持原样；另有测试头文件在本轮期间由其他工作新增内容，已保留；重叠文件只叠加本阶段改动，详见 [保护核对](ssh-stage2-2026-10-20/preservation-check.json)。

独立稳态采样显示，主要开销位于 Qt 文字布局、QML 更新和窗口合成，SSH 读取/解密/拆行占比较小。只限制可见行绘制的试跑约为 6.89%；最终三轮结果包含批次节奏调整。因此收益不单来自延长提交间隔。整窗圆角和现有玻璃效果保留。继续追求更大幅度需另行评估文字渲染或窗口合成的改造成本，本轮不扩展为新的显示内核。

## 测量条件与边界

- Apple M5 Max，48 GiB，macOS 26.6.2；Qt 6.11.1，Release，完整应用及真实 LogBackend、内嵌生产 QML。
- 窗口 1440 × 900 逻辑像素，倍率 2；同一字体、5000 行历史、同一 512 字节合成记录格式。凭据与配置隔离。
- 真实加密回环 SSH，正式性能测试使用 localhost。准备阶段一次数值回环地址反向 DNS 阻塞单独记录，未改变生产解析逻辑或系统 DNS；后续原有 127.0.0.1 连接与加密回归也通过。
- 关键 CPU 对照前后各三次、每次 180 秒。每秒检测窗口前台与可见状态，正式结果全部通过该检查。测量期间未并行执行本轮构建、采样或其他压力任务。
- CPU 为客户端整个进程，包含 Qt 和测量校验开销，不包含 Python 服务端。RSS 是进程驻留内存，不等同于 macOS physical footprint。
- 每条进入模型的压力记录检查会话、顺序、序号、固定中文/报文尾部和替换字符；没有逐字节检查填充区。分块、编码、长行、反压等功能测试另有完整内容断言。
- 压力载荷在线生成、传输和校验，未保存载荷文件；临时应用日志与配置位于已核实的 RAM 文件系统。只保留小型统计和截图。
- 呈现指标是最新记录提交对应 Qt 同步帧的代理，不证明每条中间日志都物理上屏，也不包含显示器延迟。
