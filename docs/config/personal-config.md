# 统一个人配置

个人设置的唯一活动存储为 `settings.json`。macOS 使用用户的 `Library/Application Support/LogAnalyQt`，Windows 保持程序旁的便携目录。MQTT、AI 和共享目录密码使用系统凭据存储；v4.6.0 的 SSH 测试设备连接记录在监控工作区中以明文保存账号密码。协议 XML、提示词、证书和 SSH 主机信任记录仍是独立资源。

## 文件结构

`schemaVersion` 当前为 1；分组可以缺省，缺省项使用功能原有默认值。不能把“缺省”当成显式的空数组或 false。

| 分组 | 内容 |
| --- | --- |
| ui | 窗口、列宽、透明度和编码等界面偏好 |
| parser | 默认协议 |
| mqtt | connections、selectedConnectionId、commonSubscriptions、broker、localClient、layout |
| ssh | connection、terminal、customCommands |
| ai | baseUrl、model |
| sync | protocol、prompt 的地址、用户名和凭据引用 |
| messages | version、date、presets |
| framingTemplates | 以模板名称为键的对象，避免模板同名覆盖 |
| workspace | parse 工作区及必要恢复数据 |
| resources | 后续资源引用的分组；现有证书路径保留在所属连接中 |
| retired | 已识别但当前版本不用的旧字段，供迁移回退核对，不重新启用 |

MQTT 每个连接的 subscriptions 与 commonSubscriptions 独立。没有常用订阅文件时，不从连接订阅推测补齐。工作区和命令在 JSON 内保存为对象、数组，不嵌套编码为 JSON 字符串。

所有设置写入通过共享模块更新：取得文件锁，重读当前文件，仅修改所需字段，再检查外部修改，使用 QSaveFile 提交并回读验证。更新前保留 `settings.json.previous`。MQTT 对同一工作区的跨实例冲突明确拒绝，不以旧内存覆盖对方。

## 首次启动与旧配置迁移

迁移检测在创建业务后端之前执行。检测本身只读，只有实际存在的文件才加入清单；任何一个或多个文件缺失均不构成错误。

1. 展示源文件、是否删除、密码项数量、冲突字段和来源差异。
2. 用户选择“迁移并继续”；“取消并退出”不创建默认配置、不转换、不删除。
3. 在 `migration-backups/<id>` 保存当前配置和各源的转换快照。快照不包含专用密码字段。
4. 验证配置结构、系统凭据和必要的设备安全状态；有冲突或无法识别的字段时保留原件。
5. 写入 `settings.json` 并重新读取核对。
6. 再次读取验证所有迁移密码，并检查源文件与确认时的摘要一致。
7. 只删除清单内已完成验证、且未发生变化的旧文件。
8. 在 `migration-state.json` 中记录结果及回退快照位置。

旧来源支持 LogAnalyQt.ini、MQTT 两份 JSON、两处历史预置报文 XML、preset/smart_framing 下的模板 JSON。构建目录、历史备份、release_package 和 Git 目录不进入自动处理范围。设置中可以选择旧配置目录，目录无需含 INI。显式旧配置导入只读原件，按用户确认的精确清单在下次启动导入，原件始终保留。

新 JSON 和旧配置共存时，冲突必须选定来源。多份旧来源互相冲突时停止，需通过管理入口分次导入。文件损坏、未知字段、源变化或凭据冲突均不按默认值静默覆盖。清理失败时保留剩余旧文件并报告；后续启动再次展示待处理内容。

## 密码和设备状态

- macOS 使用钥匙串；Windows 使用凭据管理器。
- AI 沿用现有绑定到服务地址的身份；SSH 绑定主机、端口和用户名；MQTT 使用独立凭据域，绑定连接标识、主机、端口和用户名；修改目标后不沿用旧目标的密码引用。
- 已有系统密码与旧明文不同，停止迁移，不覆盖任意一边。
- 系统权限拒绝、保存失败或回读不一致，旧文件不能删除。
- 系统凭据和私钥不导出，迁到另一台电脑后需要重新保存；SSH 监控工作区中的明文连接密码随配置导出。
- Windows 旧 INI 中的设备安全记录迁到 `device-state.ini`，原有用户目录副本继续使用。设备状态不进入个人备份。
- `ssh-known-hosts.json` 保持独立；导入时同一端点指纹冲突将停止。

SSH 监控工作区包含明文连接密码，自定义命令、报文和草稿也可能包含私人内容；配置导出文件和备份应按相同范围保管。系统凭据的迁移快照不是密码的额外备份，不能据此一键降级到只认识旧格式的软件。

## 设置入口和备份恢复

系统设置 → 个人配置提供状态、配置目录、备份、恢复、旧配置导入和取消待应用操作。

- 配置 JSON：仅导出个人设置，可选择是否包含工作区、草稿和历史。
- 完整备份 `.laqbackup`：JSON 容器，包含应用版本、创建时间、配置、选定资源和 SHA-256 校验。资源用 base64 保存，不加密。协议和提示词包含在内，SSH 信任记录可选；证书及私钥单独保管。
- 备份不能覆盖活动配置、资源或设备状态。备份期间检测到内容变化将失败并要求重试。
- 恢复先预览各分组是新增、替换还是一致，用户选择分组及资源。
- 确认后仅生成待恢复任务；当前运行中的设置不被替换。关闭后，下次启动先备份当前状态，再应用恢复。
- 资源失败会回退；中断恢复在下次启动先使用日志回退，避免把半完成结果当成原始配置。
- 恢复保留系统中现有匹配凭据，不自动连接 SSH/MQTT、启动 Broker、执行命令或同步网盘。外部证书路径需重新核对。
- `restore-backups/<id>` 是恢复前快照；`restore-state.json`、`restore-pending.json`、`import-pending.json` 为本机操作状态，不属于可迁移个人配置。

预置报文本地只读写 JSON。协议同步在 `cache/preset-exchange` 按需生成 XML 交换视图，下载验证后提交回 JSON。该缓存不是第二份配置来源。

## 验证范围

配置测试使用临时目录与合成凭据，覆盖缺文件、确认前只读、类型转换、密码失败和冲突、源变化、受保护目录、MQTT/预置报文/模板、备份校验与分组恢复。界面测试使用测试构建的隔离数据目录，经过真实迁移确认按钮，检查取消与确认的结果。

测试构建支持 `--ui-smoke --migration-action cancel|confirm`，仅在 ui-smoke 隔离模式下模拟点击真实按钮。正常启动没有确认绕过参数。`LOGANALYQT_TEST_HOME` 仅对测试构建生效。

如果活动 JSON 损坏，程序会在业务模块初始化前停止，原件不会被默认值覆盖。可先保留损坏原件，再使用 settings.json.previous 或已导出的备份恢复；未知的新格式版本应升级软件处理。
