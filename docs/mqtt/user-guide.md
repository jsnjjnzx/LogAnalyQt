# MQTT 调试

MQTT 调试位于左侧“通信调试”分组，采用已确认的 V2 上下布局。上方查看消息，下方编辑与发送；中间分隔条可以拖动，接收区和发送区都可以单独展开。

## 连接终端内的 Broker

1. 进入“连接终端”，打开“连接配置”。填写主机名/IP、端口、Client ID。主机栏不填写 `mqtt://` 或端口。
2. 按终端要求填写用户名、密码，选择 MQTT 3.1.1 或 5.0。Client ID 可以自动生成。
3. 保存后点击“连接”，在接收区左侧“订阅主题”列表点击“新增”，添加订阅，例如 `terminal/+/status` 或 `terminal/#`。
4. 收到消息后，在左侧记录中选择一条，在右侧查看文本、JSON 或 Hex。
5. 在下方填写发布 Topic 和内容，选择格式、QoS 与 Retain，点击发送。支持 Ctrl/⌘ + Enter。

可以保存多个连接配置、复制配置和删除配置；同时只连接一个终端 Broker。切换连接配置前先断开当前连接，需要保留当前记录时先导出。切换软件的其他页面不会断开连接。

连接配置还包括 Keep Alive、连接超时、自动重连、会话选项和遗嘱。MQTT 5 的基础连接、订阅、收发和会话有效期已接入，未提供全部 MQTT 5 属性编辑器。

TLS 为可选功能。启用后填写 CA 文件；双向认证时同时填写客户端证书与私钥。当前使用 PEM 文件，不提供私钥口令输入。证书与主机名会被校验。修改参数后需要重新连接。

## 让终端连接电脑

1. 切换到“本机 Broker”，打开“服务配置”。
2. 选择监听网卡/IP、端口。默认监听全部 IPv4 网卡、端口 1883，允许匿名连接，适用于本软件的内部调试用途。也可以关闭匿名接入，填写用户名和密码。
3. 点击“启动服务”。将界面显示的电脑局域网 IP 和端口填入终端。`0.0.0.0` 是监听设置，不能作为终端的目标地址。
4. 默认自动连接“本机测试客户端”，并订阅 `#`。可以在左侧订阅主题列表修改。本机 Broker 和终端 Broker 两种模式的草稿、订阅、消息分别管理。
5. 在同一个大数据区查看消息或向终端订阅的主题发布消息。“接入终端”面板显示其他客户端、本机测试客户端及服务事件。

本机测试客户端只显示订阅到的消息，不代表 Broker 的全部网络流量。其他客户端的 Client ID 是其 MQTT 连接声明的标识。

本软件启动自己的 Broker，不安装系统服务，也不接管电脑上已有的 Broker。端口被占用时提示失败；可以更换端口。正常退出或管理进程异常退出时，会停止对应的 Broker。

本机 Broker 为临时调试实例，停止后清除该次运行的会话、保留消息等服务状态；不保存 Broker 数据库。启动软件不会自动开启 Broker，也不会自动恢复外部连接。

## 主题列表、颜色与显示

订阅列表常驻接收区最左侧。右上方“收起订阅 / 显示订阅”可以收起或展开列表；下方发送编辑区保持全宽。

- **新增与颜色**：点击“新增”，填写主题和 QoS，从 12 种预设颜色中选择，也可输入 `#RRGGBB` 自定义颜色。已有主题右侧“⋯ → 编辑主题 / 颜色”可以修改。消息列表和详情标题中的 Topic 使用该颜色，Payload 保持原来的文本颜色。修改颜色会立即更新已有消息。
- **显示勾选**：新订阅以及旧配置中的订阅默认全部勾选。订阅三个主题时，可以只勾选一个或两个；“全选 / 全不选”批量控制接收记录的显示。取消勾选不会取消订阅，后台仍接收并缓存消息；重新勾选后，缓存中仍保留的历史会重新出现。发送记录继续由“全部消息 / 仅接收 / 仅发送”控制，需要只查看接收内容时选择“仅接收”。
- **通配符与重叠**：支持 MQTT 的 `+`、`#`。消息匹配的订阅中只要有一个勾选，就显示。颜色由所有匹配订阅中最具体的一条决定：固定主题层级越多越优先，再比较固定深度和路径长度；具体程度相同则使用列表中靠前的颜色。颜色选择不受显示勾选影响。
- **组合过滤与详情**：主题勾选与原有主题过滤、内容搜索、收发方向共同作用。当前详情消息被隐藏后，自动转到仍可显示的消息；没有匹配消息时清空详情。导出遵循当前显示选择与过滤条件。
- **真正停订**：“⋯ → 停用订阅”会取消网络订阅；“取消订阅并删除”还会移除该订阅配置。这两项与显示勾选是不同操作。
- **配置保存**：每个连接及本机测试客户端分别保存订阅颜色和显示勾选；重启后恢复这些选项。接收消息缓存本身仍不跨重启保存，并遵守原有容量上限。

## 消息操作规则

- **文本**：按 UTF-8 编码发送。
- **JSON**：先校验格式，发送保留输入的原始字节，不自动重新排版。接收区的 JSON 格式化仅影响显示。
- **Hex**：发送实际字节。例如 `00 68 FF 00` 是四个字节，空格和换行可作分隔；不接受半个字节或非十六进制字符。
- **空载荷**：文本或 Hex 模式允许发送空载荷。结合 Retain 使用时遵循 MQTT 的保留消息语义。
- **发送状态**：QoS 0 显示已提交，不声称 Broker 已确认；QoS 1/2 按协议确认更新状态。Broker 确认不代表终端已执行应用命令。
- **断线**：未连接时的新发送操作直接拒绝，不建立应用层离线发送队列。自动重连保留当前进程内已经提交的 QoS 1/2 协议状态，必要时按 MQTT 协议重传；这不是再次点击发送。QoS 1 本身允许重复交付。主动断开或退出后，不持久化未完成的协议事务。
- **过滤**：收发方向、MQTT 主题过滤器、内容/带空格 Hex 搜索只影响显示。无效主题过滤器保留上一份有效过滤结果。过滤不会修改订阅。
- **暂停显示**：继续接收并缓存新增消息；恢复显示后合并。清空只清理本地消息记录，不删除 Broker 上的保留消息。
- **发送历史**：可回填输入框，不会自动发送。每个连接最多保留 20 条，较大消息不重复保存到历史中。
- **导出**：当前已显示且符合过滤条件的记录导出为 JSONL，每行包含时间、方向、主题、QoS、Retain、状态及 `payloadBase64`。Base64 保存原始载荷，包括零字节。暂停期间的新消息在恢复显示后可以一起导出。

## 容量和显示

- 单条应用载荷最大 1 MiB；客户端在读取包体前拒绝超过 2 MiB 的 MQTT 包。
- 主消息缓存最多 10,000 条或约 64 MiB 的主题/载荷数据，达到上限淘汰最早记录。
- 后台接收队列及暂停队列各自有 2,000 条/8 MiB 上限；超出时显示丢弃计数。
- 长消息预览前 64 KiB；界面提示截断，复制和导出仍使用完整原始载荷。
- 每个连接最多 100 个订阅，最多保存 64 个连接配置。

## 配置位置

按内部测试软件的要求，用户名和密码直接保存在 JSON 配置文件中，不使用系统凭据存储。

- macOS：`~/Library/Application Support/LogAnalyQt/mqtt/connections.json`。
- Windows：EXE 同目录下的 `mqtt/connections.json`。

配置包含连接参数、订阅及其颜色和显示勾选、发送草稿、发送历史和分区比例。消息记录不随配置持久化，需要保留时使用导出。

保存采用替换完整文件的方式；保存失败会显示原因。损坏或不支持的配置文件会保留，软件不会静默覆盖，请处理该文件后重启。

Windows 仍分发一个 EXE。首次使用本机 Broker 时，内置辅助程序释放到配置目录中的 `mqtt/runtime/<内容标识>/` 后运行，不需要另行下载安装。macOS 的辅助程序位于 `.app/Contents/Helpers/`。

## 当前范围

本次不包含 WebSocket、脚本自动化、压力测试工具、Broker 集群/桥接管理或协议解析联动。Windows 和 macOS 的实现与构建入口均已接入；各平台的实际验证结果单独记录在 `validation/mqtt/README.md`。

## 从源码构建

需要 CMake 3.24+。首次构建下载固定版本的 Mosquitto 和 cJSON 源码，并校验 SHA-256；应用运行时不下载这些组件。

Windows 沿用现有静态 Qt / MinGW 工具链。新增的构建机依赖是 MSYS2 的 `make` 和 `perl`，通过 `LOGANALYQT_MSYS2_DIR` 指定 MSYS2 目录（默认 `C:/msys64`）。运行 `scripts/package_single.ps1 -BuildTests` 会准备并缓存静态 OpenSSL，然后生成单 EXE。可用 `LOGANALYQT_MQTT_OPENSSL_DIR` 指定缓存目录。CI 已配置这些构建步骤；普通使用者不需要安装 MSYS2、OpenSSL 或 Mosquitto。

macOS 使用现有 Homebrew Qt / OpenSSL 环境及 `macos-debug`、`macos-release` 预设。`scripts/package_macos.sh` 会将 Broker 放入应用包、规范化复制库的路径标识，再执行签名和打包。
