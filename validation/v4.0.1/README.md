# V4.0.1 Mac 更新后主窗口恢复

## 问题与范围

用户反馈点击“立即更新”后应用关闭，未再次看到窗口，且没有手动重新打开。
现场只读检查确认安装包已替换、新进程已启动；常规隔离更新可以正常显示窗口，未完整复现现场的窗口不可见条件。
原有回归只确认新进程渲染过一帧、版本与数据正确，没有检查窗口可见性与前台焦点。

本次增加显式窗口恢复：Mac 原生启动完成 QML 加载后，在事件循环中恢复隐藏/最小化的主窗口、提升窗口并请求激活。正常显示的窗口不改变其最大化或全屏状态。
该行为位于新应用的启动流程，因此 V4.0.0 的旧更新器也能启动并激活 V4.0.1。
Mac 更新器改用 `open -n`，明确启动目标应用的新实例。更新按钮标为“立即更新并重启”。

没有修改下载校验、版本替换、数据迁移、工作区保存或 Windows 更新器逻辑。

## 本地验证

- 负对照：保留旧启动行为，模拟隐藏主窗口；新增检查失败，原因为没有可见窗口的首帧记录。
- 修复后：真实 Cocoa 环境下，隐藏和最小化两种状态均恢复并渲染，窗口可见且激活。
- 四组针对性回归通过：更新检查、页面/工作区恢复、Mac 窗口激活、更新替换与失败回滚。
- 发布后更新测试增加 `visible` 校验，以及 Mac `active` 校验，不再将进程重启直接视为窗口显示成功。

测试在临时应用副本和临时数据目录中执行，未替换用户的 `/Applications` 安装或改写正式配置。
本目录的 `activation-before.log`、`targeted-tests.log` 为本地验证日志，不纳入源代码。

## 发布验收

使用 V4.0.1 标签触发既有双平台构建和发布后真实更新测试。另以 V4.0.0 的正式 Mac 安装包验证旧更新器到新应用的过渡。
现场具体的 macOS 隐藏/焦点条件未被完整复现；交付依据为显式恢复逻辑、失败对照、原生窗口检查及实际版本过渡验证。
