# AI 698 提示词维护说明

默认文本：[ai_698_framing.md](ai_698_framing.md)。本说明供测试和维护人员阅读，不会随提示词发送给模型。

## 修改位置与生效方式

- **改本机行为**：在应用“系统设置 → AI 组帧提示词”查看实际路径，通过“打开提示词文件夹”编辑该目录下的 `ai_698_framing.md`。
- **改后续构建的默认文本**：编辑仓库 `prompts/ai_698_framing.md`，重新构建后随应用资源打包。已有本地文件不会被新默认文本自动覆盖。
- **已有本机采用新版默认文本**：先将原文件备份到提示词目录之外，再手动用新版默认文本替换，并合并需要保留的个人经验。不要直接删除旧经验。
- 保存为 UTF-8，文件非空、不含空字符，总大小不超过 64 KiB。Markdown 标题和列表只用于分段；整个提示词文件都会发送给模型，HTML 注释也不会被过滤。维护日志和未填写的模板放在本说明或测试记录中。
- 保存后从**下一次新组帧任务**生效；当前追问继续使用提交时的提示词版本。提示词文件不支持变量替换，不要加入等待程序展开的占位符。
- 沿用现有“AI 提示词”同步入口；同步前核对内容，按应用提示处理冲突。“加入 698 提示词”会在文件末尾追加“用户补充经验”，仍建议定期整理去重。

## 按什么位置修改

| 想调整的内容 | 放置位置 |
|---|---|
| 职责、事实来源及不可绕过的约束 | 第一节；需要结合实现审查，不作为日常业务经验随意改动 |
| 工具名、输入字段或调用顺序 | 第二、三节；先核对实现，修改文字不会新增工具能力 |
| 应该问什么、何时询问、记录范围选择 | 第四节 |
| 冻结终端、目标冲突、业务通信地址、代理目标 | 第五节；需要结合实现审查 |
| 数值填写方式、成功标准、回复方式 | 第六节 |
| 某种业务的已验证处理经验 | 第七节或文末“用户补充经验” |

一条规则只描述一种场景。已有规则不合适时修改原条目，避免在文末不断叠加相反的规则。不要把一次回答中的推测、固定 OI 或测试输入直接写成所有业务的通用规则。

## 补充经验的文本格式

复制以下格式，填写完成后再放入提示词；不要把未填写的模板留在实际提示词中：

```text
### 经验：简短名称
- 适用场景：用户在什么情况下提出什么需求。
- 处理规则：先查什么；满足什么条件时如何处理；缺什么时询问。
- 示例：用户怎样提问，助手应该怎样处理。示例值不作为默认参数。
```

例如以下规则已经存在于默认文本的第四节，展示的是写法，无需重复追加：

```text
### 经验：读取记录时先确认行范围
- 适用场景：用户要求读取某类历史记录，但没有说明读取范围。
- 处理规则：先查询对应记录定义，再询问最近几条、指定条目、时间范围或全部；不自行选择范围，不要求用户填写将要读回的值。
- 示例：用户说“读取停电记录”，应询问读取范围；用户说“读取最近一条停电记录”，则按定义处理，不再重复询问范围。
```

## 修改后的人工验证

每次修改后新建组帧任务，保留用户输入、提示词版本、实际回答和工具结果；同一模型的回答可能变化，关键场景应重复验证。

| 场景 | 预期行为 |
|---|---|
| 信息完整、当前本地定义支持的普通读取 | 查询定义并构建一条报文，不重复询问已有信息 |
| 读取历史记录，但没有范围 | 查询定义后询问范围，不直接按全部或最近一条构建 |
| 明确读取最近一条历史记录 | 按历史记录定义选择行列，不改成当前值或累计统计 |
| 写入请求缺少定义要求的业务字段 | 按定义询问缺项，不凭经验填写数值、长度或格式 |
| 使用“当前终端”与另给一个冲突目标，分别测试 | 前者不重复确认目标；后者先澄清，不静默套用冻结终端 |
| 修改通信地址属性，或包含代理内层 TSA | 区分业务地址和外层目标；仍按定义补齐业务参数 |
| 本地定义不支持，或请求绕过校验手写 HEX | 说明具体缺口，不伪造报文或声称构建成功 |
| 本次修改新增或调整的业务场景 | 同时验证正常输入、缺项输入及相近但不适用的场景 |

文件加载与快照等程序回归见 `tests/ai_controller_tests.cpp`，工具约束见 `tests/ai698_tools_tests.cpp`。这些自动测试不证明真实模型会遵循文本规则，仍需上述人工验证。
