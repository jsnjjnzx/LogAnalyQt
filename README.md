# MultiProtocolParser (Log Analyzer)

**当前项目版本：** v4.1.0 — see `CHANGELOG.md`

一个功能强大的多协议报文分析与日志查看工具，专为分析 16 进制数据和调试通讯协议而设计。

## 🛠️ 主要功能

### 🔍 核心解析引擎
- **自动协议检测**：粘贴报文即可自动识别协议类型（698、AppMsg、ModuleMsg、101/104、376.2、645、南网计量上行规约等）。
- **南网计量上行规约解析**：严格校验 FT1.2 双长度、校验和与结束符，并识别附录 I 的 `88H + 标志 + 小端长度 + 载荷 + 77H` 外层。XML 采用相互独立的 AFN 服务表和 DI 数据项表，已登记规范正文 17 个 AFN 和 667 个 DI 精确/系列键；支持参数、测量、任务、告警、事件、文件、中继、安全、自定义和数据转加密的代表结构。普通/中继/表端/推送任务号范围由业务解析器归一化为 `XX` 系列查表键；`BIN`、BCD 时间、动态数量/长度和内层 DI 引用由解析器固定处理。文件段 CRC 保留接收原文；规范只明确多项式为 `0x1021`，未明确初始值、反射、异或输出和覆盖范围，因此不自行显示通过或失败。规范无法唯一确定边界的复合记录、密文、压缩载荷和厂商私有数据会明确保留原文；解析器不执行文件写入、升级、解压、解密或厂商插件调用。智能组帧不在本阶段范围内。
- **南网日统计数据**：`E1008010`、`E1008015`～`E100801A`、`E100801D` 的 `MMDDhhmm` 按低字节在前解析；`E1008011`、`E1008012`、`E1008013` 三相电压合格率和 `E1008041` 日失压数据均已展开到独立字段。
- **16进制提取**：智能算法自动从光标所在行提取最可能的 16 进制数据片段。
- **对比模式**：支持左右分屏对比两条报文的解析差异，并支持同步滚动。

### 📂 日志查看与管理
- **多编码支持**：自动检测 UTF-8, GBK, UTF-16 等多种编码，支持实时切换。
- **高效搜索**：内置正则搜索、高亮显示及搜索结果实时定位功能。
- **数字排序**：自动识别日志文件中的数字版本并按时间序排列。

### 🔎 内容过滤与搜索

- **实时搜索**：内置搜索框，支持向前/向后搜索，支持循环查找
- **高亮显示**：搜索结果自动高亮并显示匹配数量
- **快捷搜索**：Ctrl+F 快速搜索选中文本
- **智能占位符**：输入框提供友好的使用提示

### 🔣 编码支持

## ⚙️ 配置说明

### 协议规则定义 (XML)
本工具通过外部 XML 文件定义解析规则，支持非侵入式扩展：
- **app_msg_protocol.xml**: App 通讯协议结构。
- **698_protocol.xml**: DL/T 698.45 协议及 OAD 定义。
- **module_msg_protocol.xml**: 内部模组通讯协议。
- **3762_protocol.xml**: 国网/南网 376.2 协议。
- **645_protocol.xml**: DL/T 645-1997/2007 协议。
- **csg_upstream_protocol.xml**: 南网计量上行规约独立的 `AFNs + DIs` 字典（v2.0.0，17 个 AFN、667 个 DI 键）；AFN 自身定义上下行 `Service`，程序分别查询 AFN 与 DI 后组合解析，不在 XML 中绑定两者。`E00003XX`、`E00004XX`、`E00015XX`、`E00016XX` 等是业务解析器生成的系列查表键，不是 XML 通配表达式；`XX` 的范围归一化和基础类型解码由业务代码处理。

### 协议 XML 同步 (SMB)

- 本项目新增协议 XML 网盘同步功能，支持通过 SMB/CIFS 连接到网络共享或 NAS，自动同步 `protocol_xml/` 目录下的定义文件。
	- 支持用户名/密码认证或匿名访问。
	- 支持定时同步和手动触发，同步时仅传输差异文件以节省带宽。
	- 南网计量上行规约 XML 在上传和下载前执行语义校验，合法文件下载后立即热加载，无需重启程序。
	- 冲突检测：在检测到本地与远端同时修改同一文件时，会保留本地副本并提示用户处理选项。
	- 配置与管理入口：请查看程序内的 `协议同步` 对话框（`ProtocolSyncDialog`）或使用 `ProtocolSyncManager` 的配置参数。

## 📦 构建与打包

本项目包含 Windows 和 macOS 一键打包脚本。自动更新要求将主程序包和
同名 `.sha256` 文件和 `update.json` 一起上传到同一个 GitHub Release。

### Windows

运行环境：Qt 6.11.1 静态版（MinGW 64-bit）、CMake、PowerShell。

```powershell
powershell -ExecutionPolicy Bypass -File ./scripts/package_single.ps1 -Version 3.1.1
```

脚本生成：

- `release_package/LogAnalyQt_v<版本>_Windows_x64.exe`
- `release_package/LogAnalyQt_v<版本>_Windows_x64.exe.sha256`

构建机可通过 `QT_STATIC_DIR` 和 `MINGW_DIR` 环境变量覆盖脚本中的默认工具链路径。

### macOS

本地开发使用 Debug 构建（只生成调试程序，不参与打包）：

```zsh
cmake --preset macos-debug
cmake --build --preset macos-debug
```

生成可独立运行和自动更新的发布包：

```zsh
./scripts/package_macos.sh
```

脚本生成：

- `release_package/LogAnalyQt_v<版本>_macOS_<架构>.dmg`
- `release_package/LogAnalyQt_v<版本>_macOS_<架构>.dmg.sha256`
- `release_package/LogAnalyQt_v<版本>_macOS_<架构>_update.zip`
- `release_package/LogAnalyQt_v<版本>_macOS_<架构>_update.zip.sha256`

DMG 用于用户首次安装，`_update.zip` 专供程序内自动更新。当前 GitHub 发布使用
ad-hoc 签名，不需要额外 Secrets；尚未完成 Apple 公证或首次下载的 Gatekeeper 验收。
以后启用 Developer ID 签名及公证时，可使用：

```zsh
MACOS_CODESIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)" \
MACOS_NOTARY_PROFILE="LogAnalyQt-notary" \
REQUIRE_MACOS_DISTRIBUTION=1 \
./scripts/package_macos.sh
```

macOS 更新包内必须只包含一个 `LogAnalyQt.app`。应用会按当前系统和 CPU
架构选择发布资产，校验 SHA256 和代码签名后再执行原子替换。

### GitHub Actions 云端双平台打包

推送到 GitHub 仓库 `main` 或推送 `vX.Y.Z` 标签，自动运行
`.github/workflows/build.yml`；也可在 Actions 页面手动运行。
标签必须与 CMake 项目版本一致。`main` 推送和手动运行只构建、测试、保存产物；
只有推送版本标签才会在双平台验证全部通过后发布正式 Release。

- Windows：`windows-2022` x64，Qt 6.11.1 静态版 + MinGW 13.1，生成单文件 EXE 和 SHA256。
- macOS：`macos-15` arm64，Qt 6.11.1，生成 DMG、更新 ZIP 和各自的 SHA256。
- 两个平台分别执行 Release 构建、自动测试、打包及产物检查；Windows 检查 PE 架构为 x64，macOS 检查包内程序和库包含 arm64 且不引用构建机上的外部库。
- 打包后再执行隔离启动回归；Windows 会临时隐藏构建机的 Qt 安装目录，确认单文件 EXE 不依赖开发环境。
- Windows 静态 Qt 首次从 Qt 官方 GitHub 源码构建并缓存；缓存丢失时自动重建，首次运行较慢。
- 构建包在 Actions 对应运行记录的 Artifacts 下载，保留 7 天。普通构建无需配置额外 Secrets。
- macOS 构建包目前采用 ad-hoc 签名，未完成 Developer ID 签名与 Apple 公证，不视为正式分发验收。

构建目录、安装包、日志、个人配置和本地 Git 恢复备份不纳入版本控制。
现有 `.workflow/` 与 Gitee 发布脚本属于历史参考，GitHub Actions 不执行它们。
程序内更新通过 `https://github.com/jsnjjnzx/LogAnalyQt/releases/latest/download/update.json`
获取版本、平台包地址和 SHA256，不使用客户端 Token。缺少对应平台包、校验值或版本信息异常时拒绝自动安装。

发布时只给发布任务授予 `contents: write`，使用 Actions 自带的 `GITHUB_TOKEN`，无需个人 Token。
流程先创建草稿，上传三个包、三个校验文件和 `update.json`，核对 GitHub 返回的全部附件大小与 SHA256 后再公开。
失败时保留草稿供重试；已经公开的同版本 Release 禁止覆盖，应提升版本号再发布。
正式发布后，Windows 和 Mac 会分别从该 Release 执行一次隔离更新演练：模拟旧版检查、下载、校验、
保存工作区、替换、重启，并核对用户数据。Mac 演练使用独立临时用户数据目录，Windows 使用临时便携目录，不读取或替换开发者及用户的现有数据。

发布新版本的操作顺序：修改 CMake 项目版本和 CHANGELOG，推送 main 并确认构建通过，再推送对应 `vX.Y.Z` 标签。
首个 GitHub 迁移版为 `v3.1.1`。已经分发的 Gitee 旧版需要手动安装本版一次，此后从 GitHub 更新。
